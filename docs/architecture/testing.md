Keep domain and protocol tests independent of widgets wherever possible. Inject I/O at the established store/transport boundaries rather than introducing a second production implementation merely for tests. A fake channel can reproduce silent `open` transports, partial delivery, blocked writes, and stale-generation callbacks that are difficult to time reliably against public services.

Historical room-page tests use an injected test editor to preserve lifecycle coverage. Separate production-editor tests exercise the actual `TreeEditor` and the production profile's **`familyTree`, `familySurnames`, `personalSurnames`, `explicitSiblings`, `patronymics`, `marriageHistory`, and `authorHistory`** requirements, including empty rooms. The production identity-aware profile additionally requires **`participantIdentity`**, so a legacy peer cannot silently miss binding-release semantics. Passing the legacy test seam or its old text-preview exchange alone is not evidence that the current canvas/author-aware entry works.

## Author-Prefix Regression Boundaries

The pure record, history, storage, and session suites provide focused assertions for:

- strict optional proof fields, exact sorted legacy bases, all operation kinds in one per-actor sequence, holes/forks/cross-author links, and unexpected late legacy records after sealing;
- unchanged old record bytes/digests and tree conflict stamps, real UTC creation instants despite clock rollback, and topological ready-set ordering rather than timestamp sorting;
- immediate stable-core optimistic drafts while the writer waits, whole outstanding backlog retries, no dependent tail after a failed predecessor, reuse of committed proofs, and allocation after intervening same-actor writers;
- canonical full-history results, complete prefix validation before incoming writes/ACK, recursive outbound predecessor/base closure despite inventory claims, and logical checkpoint cutoffs resolved only after flush;
- shared browser journal locks for authoring/imports/loads, visible missing-lock errors, retained saving failures, and flush-before-controlled-exit.

These are executable test contracts, not a claim that every suite ran or that mocks establish real cross-tab behavior.
For storage/UI/network changes, a **headless release-browser** check must also exercise the relevant real boundary: same-profile
same-actor tab bursts, an independent profile receiving complete history, delayed/failed persistence and retry, reload of
canonical prefixes, and local-saving/error/exit behavior. Inspect actual stored proof chains and payload/core equality,
not only the current text, history length, or a screenshot. A timezone-sensitive check should distinguish the unchanged UTC
instant from locale rendering; a wall-clock rollback must not be mistaken for a new sequence source.

The existing drivers below describe their own assertions; an older collaboration/canvas pass does not automatically verify
these author-prefix races. Report the actual focused scenario, browser errors, persisted-state evidence, and any unrun cases
in [verification records](../verification.md). A compiled browser suite or an unavailable harness is not real-browser proof.

## Standard Checks

The Pages workflow injects `MYTREE_BUILD_VERSION` as a UTC date/time compile-time value. To stamp a local verification release, pass `--dart-define="MYTREE_BUILD_VERSION=yyyy.MM.dd-HHmmss UTC"`; without it, the room menu honestly shows `dev`. The version row supports text selection/copy and must remain the final non-action menu entry, without disabled button/menu-item semantics around its read-only text field.

From the project root:

```bash
flutter pub get
flutter analyze
flutter test
node --test tool/serve_web_test.cjs
flutter build web --release --no-web-resources-cdn
```

Run real browser checks **headless** for UI/network changes, as required by [CLAUDE.md](../../CLAUDE.md). Do not open browser windows or take over the user's desktop. A skipped, compiled-only, or failed test is not a passing test; retain that distinction in reports.

## Read-only live Disk re-entry benchmark

[check_disk_reentry.cjs](../../tool/check_disk_reentry.cjs) measures a served release in headless Chrome using an explicitly supplied local token file:

```text
node tool/check_disk_reentry.cjs <playwright-module> <token-file> <base-url> <new-artifacts-directory> [room-id]
```

It reads existing cloud batches, seeds an isolated accepted local profile, then performs repeated same-profile reloads (`DISK_REENTRY_REPEATS`, default three). It checks complete journal equality/digests and fresh successful provider reads, recording tree-entry readiness separately from subsequent cloud-copy acknowledgment. It never clicks Retry or Open Local Copy. Provider mutations, upload/publication endpoints, and all WebSockets are blocked; this isolates Disk entry rather than claiming public RTC verification. Reports contain counts, sanitized request categories/timings and hashes, not credentials, signed URLs or journal bodies. Readiness failures remain recorded failures, not timings for a successful entry. Use a fixed room ID for before/after comparison; live account/network latency is dated evidence, not a guarantee.

## Real Application Driver

[check_tree_ui.cjs](../../tool/check_tree_ui.cjs) drives the current production tree UI through Playwright/installed Chrome:

```text
node tool/check_tree_ui.cjs <playwright-module> <base-url> <screenshots>
```

The first argument is a module name or a path resolvable by Node's `require()`; Playwright and a compatible installed Chrome must already be available. The URL points to a served release build. The output directory receives screenshots, including failure captures.

The script uses independent desktop/mobile browser contexts and real public signaling with forced TURN. It creates relatives through the UI, edits biographies and facts, uploads an image through the file picker, chooses an avatar, checks mode choices, compares complete persistent operation sets, verifies guest permissions and person-linked devices, and reloads saved state.

An optional trailing `guest-identity` runs the focused editor-only binding scenario: independent editors can bind and share a displayed identity, while a guest has no binding action or bound-profile caption and stays separate until a durable promotion and explicit binding. An explicit participant alias remains the displayed name even when bound; grouping does not replace it with the person's name. Isolated real-storage legacy fixtures retain old guest claims without using their person name/avatar or merging their actors. The default collaboration scenario likewise binds only editor profiles. Run scope and actual results belong in [verification records](../verification.md), not in this driver description.

The focused `identity-local` mode isolates public transport and uses real storage plus actual desktop/phone UI. It checks nonempty alias precedence, clearing to a bound given name (without surname) or `Аноним`, a real hover tooltip containing the full bound-person name and a truncated alias, editor/guest command restrictions, and the name modal's own-device release. Release must preserve the typed alias and append exactly one `unbindActor` targeting the immutable binding ID, without mutating that binding or releasing another device. It then saves/clears an alias, explicitly rebinds, validates complete author-prefix history, and reloads without hidden writes. Fresh blank-name forms distinguish acceptance from actual guest admission: an unavailable real peer is not reported as a successful join. A locally created anonymous editor is durably reloaded without another name prompt. These local checks do not establish public RTC convergence.

The diagnostic `identity-actions-local` case independently checks the own-name modal at a phone viewport, without a tooltip or roster-rectangle prerequisite. Through actual dialog buttons it releases the exact own binding, preserves an unsaved alias while leaving the modal open, saves and clears that alias, and reloads the complete immutable author-prefix journal. Roster text must show `Аноним` for the released device and retain the other device's separate bound identity; biography must offer `Это я` again after reload. This limited case does not establish hover-tooltip behavior, guest admission, or a pass for the broader `identity-local` mode.

The finite `dialogs-local` case reuses the `identity-actions-local` phone flow and its explicit pre-load fixture, blocks **all** off-origin requests, and never requires public peers. The own-name modal must retain only its name field, own-device unbind action when bound, Save/Cancel, and actual failure text—not helper paragraphs or a static bound-person caption. Actual unbind/save/clear/cancel commands preserve immutable history and the unsaved draft. A separate `Это я` confirmation contains one full-name question and two buttons, without permission or cancellation instructions. The case also temporarily rejects browser-storage operation appends at the I/O boundary: a failed name save must keep the dialog/draft and visible error; retry commits the same record, then a complete-journal reload is checked. Intermediate snapshots inspect page errors and console errors plus Flutter rendering failures at every console level. This is a local release-browser scenario, not evidence of public synchronization or hover-tooltip behavior.

## Release Serving

[serve_web.cjs](../../tool/serve_web.cjs) is a developer static server, not a database, signaling broker, authentication service, or runtime requirement for end users. It serves the generated bundle with:

- JavaScript/wasm Brotli or gzip when accepted;
- content-derived `ETag` values and conditional 304 responses;
- MIME types, GET/HEAD handling, and containment checks against escaping the build directory.

[serve_web_test.cjs](../../tool/serve_web_test.cjs) verifies these behaviors, including changed-build cache invalidation. Serve only the intended build directory:

```bash
node tool/serve_web.cjs build/web 52173
```

`--no-web-resources-cdn` includes renderer resources locally instead of requiring a separate CanvasKit CDN fetch. The HTML preloads the JavaScript entrypoint and the font manifest/icon-font fetches so they overlap loader/engine startup, rather than forming a later font-request waterfall. It does not bypass Flutter initialization, legacy service-worker cleanup, or room verification. The normal Flutter web development server is still suitable for development, but its serving/caching characteristics are not equivalent to the compressed release setup used for loading measurements.

A temporary HTTPS tunnel can expose the web bundle to a phone. It does not replace TURN, persist room data, or establish permanent hosting. Changing its origin changes browser storage. Do not publish a workspace or create external infrastructure silently.

## Interpretation and Remaining Limits

- Localhost page delivery with public signaling/TURN tests real transports, but not slow application downloads through a public tunnel.
- Mobile emulation verifies viewport/layout behavior on that browser, not physical-phone suspension, camera behavior, or every mobile network.
- Independent browser contexts are independent participants; ordinary same-profile tabs intentionally share an actor and network owner.
- Public signaling/TURN can fail independently of the code. Record external failures rather than weakening durability or presence assertions to obtain a pass.
- The recorded environment lacked the Android SDK and full Windows desktop toolchain. Web builds do not validate those native targets.
- There is no service SLA or guarantee of bounded recovery time during a network partition or provider outage. The optional Disk replica is an additional copy, not an independent archival-retention guarantee; its acknowledgment must be verified separately from local/WebRTC state.

For changes to protocol, identity, or storage, test the invariants in their subsystem documents as well as the happy-path UI.
