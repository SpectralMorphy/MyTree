# October 22, 2026 — Stepparent emphasis and parental-family proximity

## Scope

A direct parent's additional co-parent now receives `TreeEmphasis.cousin`, not `distant`. The standalone fix is independent of the separate marriage/surname-history feature. In the combined working snapshot verified below, that feature additionally supplies projected marriage partners to the same presentation rule. Normal ancestry/descendant/sibling membership still wins. This presentation rule does not extend to the stepparent's ancestors or siblings, create ancestry, or change stored relationships. The existing connection painter therefore mutes the stepparent's curve to a half sibling while retaining the actual shared parent's normal curve.

The final family-proximity refinement requests a compact whole-block parent/stepparent cluster, after own/sibling partner priorities and subject to existing structural locks. Unrelated blocks stay present but outside a compatible cluster. Canonical sibling members, actual ancestral seams, generation ranks and immutable history remain unchanged. The extra objective is absent when there is no stepparent.

## Regression evidence

The two added layout tests failed before the production change: stepparent emphasis was `distant` instead of `cousin`, and an unrelated block widened a three-block parental cluster to four slots. The complete layout suite subsequently passed **110 tests**. The checks retain both real half-sibling parents and verify cousin photo/block treatment, muted `.40` stepparent curves, normal shared-parent curves, unchanged journals and father-only slot exchanges.
